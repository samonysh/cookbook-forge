#### 🔍 可读性与组织层自检（交付前过一遍）

**句子与段落**

- 章首：前两句是困境与代价，不是概念名。
- 小节：第一段先交代「什么时候会遇到」，再给定义。
- 术语：首次出现有一句白话解释（`就是 / 即 / 指的是 / 可以理解为`）；缩写（MCP、HITL、OTel）首次出现带全称或白话括注。
- 段落：首句是主题句，≤70 字，不以「因此/所以/但是/此外」直接开头。
- 句子：单句 ≤120 字（>180 必拆）；≥5 个逗号且 ≥100 字必须拆。
- 句法：没有「对……进行……」「对……的实现」这类名词化；每句有明确主语。

**章与节**

- 章弧：N.0 有一句可回答的问题；N.8–N.9 回到同一个问题，并写「原来以为…现在知道…」。
- 问题链：每个 H2 首句承接上一节（回指结论 / 点出缺口 / 复用术语），末句移交或关闭问题。
- 漏斗：第一个正文节是应用线；每个原理节首段回指应用线里出现过的具体现象；连续原理节不超过 4 个。
- 单弧：一个 H2 只回答一个问题，H3 ≤6（≥8 会被 `G5` 报）；标题能看出本节在论证什么。
- 论证：原理/综合节能指出判断、理由、证据、锚点、限定、回应六样东西；全章原理线至少有一个代码/图/表/源码证据锚。
- 术语主线：N.0 点名的核心术语 ≤5 个，全章一种叫法，章末复现。
- 章末：最后两节不首次引入新术语或未解释的缩写。

- 跑 `node scripts/chapter-lint.mjs --root=<book>`：W1–W6 与 G1–G5 全部处理，或写 `<!-- lint-ignore: Wx/Gx -->` 并注明理由。
- 完整规则见 `references/readability-style-guide.md`（句段层）与 `references/narrative-structure-guide.md`（组织层）。
